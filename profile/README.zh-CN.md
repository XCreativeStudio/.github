## 怎么做的

XCreative Studio 就一个人。做的都是小工具，起点通常是某件把我烦到的事；做出来发现别人也用得上，就留着继续维护，用不上就关掉。

下面这几条是踩过坑之后才想明白的：

- **先弄清问题，再写代码。** 说不清是谁遇到它、现在怎么应付，那就是在给自己做东西。这没什么不行——但要清楚是哪一种。
- **选无聊的方案。** 宁愿做一个两年后我还能维护的小东西，也不做一个自己接不住的漂亮东西。
- **早点发出去。** 我对「用户想要什么」的猜测错得够多，等到有把握再发，代价更大。
